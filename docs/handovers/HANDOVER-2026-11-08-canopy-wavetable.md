# CANOPY: factory wavetables, scanning and expression

Branch: `codex/short-loop-proof`. DTII OS 1.17 only. Evidence is [D]/[O],
not independently image-audited [V]. This update implements the user's
wavetable proposal; it does not add FM, PWM, hard sync or user-table imports.

## Implementation

CANOPY retains Velvet/Reed as engine families 0/1 and adds WAVETABLE as family 2.
Five original factory tables (ANALOG, GLASS, VOCAL, ORGAN, METAL) each contain
eight frames and seven pitch-filtered levels. Data is reproducibly generated by
`tools/patchkit/canopy_wavetables.py` into `src/dsp/wavetables.s` and compiled into
the module. No sample upload or storage access is needed to change a table.

The new renderer interpolates waveform phase, table position and filter levels.
The existing oscillator remains the phase authority for tuning, bend, drift and
same-pitch pad/arp alignment. Shared scanning offers sine, triangle and smooth
random shapes; free, phrase and pattern restart; free frequency or tempo sync.
Clock loss holds a master-synchronized scan. Position, depth and live expression
are smoothed. Table changes use a bounded transition with only the latest pending
request retained. Source changes preserve the existing voice layout and use a
bounded transition. Four held notes, an arp and release tails retain their
existing ownership and allocation rules.

Per-note timbre envelopes are independent of amplitude envelopes. Arp voices
inherit their parent note's timbre state. Signed envelope, velocity and mod-wheel
amounts default to zero. USB and DIN CC1 state belongs to its port/channel route;
CC121 clears that route's wheel, and CC120 stops sound without changing it.
Position modulation clamps at the table ends rather than wrapping.

The instance grows from 800 to 1184 bytes, preserving the original 200-word
prefix. Added words 200-231 hold eight token/envelope/route records; words
232-263 hold scan and transition history; words 264-295 hold USB/DIN wheel state.
The descriptor and adapter policy agree on a 100,000-instruction process ceiling
and 1,600-instruction reset ceiling. These are instruction limits, not a physical
worst-case timing claim.

## Controls and native UI

CANOPY SETUP row 18 is now an ENGINE chooser, replacing the old REED toggle.
The SRC cycle is SOUND, ARP, TONE. SOUND and TONE use native TUNE at A, source LEV
at H, the dedicated track LEVEL/DATA control and the native held-SRC value mode.
The firmware-owned native page vector grows safely from two entries to three;
registration alone is not enough to extend the original allocation.

| TONE encoder | Control | Display |
| --- | --- | --- |
| A | TUNE | Unchanged native tuning |
| B | TABL | ANLG, GLASS, VOCAL, ORGAN, METAL; full ANALOG in turn feedback |
| C | POS | 1.00-8.00, interpolating between the eight frames |
| D | DEP | 0-100%; full depth reaches 3.5 frames either side |
| E | HZ / RATE | 0.01-10.00 under HZ; 4BAR, 2BAR, 1BAR, 1/2, 1/4, 1/8, 1/16 when synchronized |
| F | SHAP | SINE, TRI, RAND |
| G | RST | FREE, TRIG (phrase restart), PATT |
| H | LEV | Unchanged native source level |

Custom value cells are bounded to five characters. Full free-rate units appear
in feedback, e.g. `Scan Rate=10.00 Hz`. Wavetable-only TONE controls show `--`
and reject edits while Velvet/Reed is selected. SOUND D becomes POS for
WAVETABLE, sharing the same parameter as TONE C while preserving the legacy
COLOR value. Setup row 19 directs users to SRC D for position.

The WAVETABLE TIMBRE submenu provides scan-clock selection, timbre attack/release
and signed envelope/velocity/wheel amounts (-100..100 percent of the table).
It follows SAVE ROUTING, retaining LEARN at setup row 13 and PRESETS at row 34.

## Versioned contracts

CPS9 (`0x43505339`) remains a 32-word configuration bank. Header word 0 has
version 9 in its low byte and retains mode/native TUNE. Family word 1 permits 2.
The original words 0-15 retain their meanings. Words 16-31 retain the original
sixteen presentation controls in their low 16 bits. High halves of words 16-27
carry the twelve new controls; high halves of words 28-31 must be zero.

| Stable control ID | Name | Range / default |
| --- | --- | --- |
| 16 | WT_TABLE | 0..4 / 0 |
| 17 | WT_POS | 0..700 / 0; display is 1 + value/100 |
| 18 | WT_DEPTH | 0..100 / 0 |
| 19 | WT_RATE | 1..1000 / 10 hundredths Hz; 1..7 when synchronized |
| 20 | WT_SHAPE | 0..2 / 0 |
| 21 | WT_RESET | 0..2 / 0 |
| 22 | WT_CLOCK | 0..1 / 0 |
| 23 | WT_ENV | 0..200 / 100; signed amount with +100 bias |
| 24 | WT_ATTACK | 0..127 / 5 |
| 25 | WT_RELEASE | 0..127 / 15 |
| 26 | WT_VELOCITY | 0..200 / 100; signed amount with +100 bias |
| 27 | WT_WHEEL | 0..200 / 100; signed amount with +100 bias |

Detail status schema 3 publishes controls 0-27 and native TUNE at index 28.
Ownership tokens remain at detail indices 38-41. The CF receiver retains legacy
schemas; schema 2's native TUNE is translated from index 16, and it cannot clear
new wavetable pending markers. Pending bits remain revision- and value-bound.
`IsStatus.fast_valid` remains at word 158, `CsState.pending` at word 4, and
`CvDisplay` layout is unchanged for existing runtime diagnostics.

CPST v3 uses 96 bytes. Original controls and metadata retain their byte offsets;
new control words occupy bytes 64-87, factory-table version 1 is at byte 88,
reserved bytes are canonical zero, and bytes 92-95 contain the checksum.
Legacy 64-byte v1/v2 records are fully validated, migrated and canonicalized in
RAM without automatically rewriting the card. V1 retains its upward octave
meaning through the existing signed-spread migration. Older presets stay on
Velvet/Reed and receive neutral wavetable defaults. Unsupported table versions,
invalid ranges, noncanonical padding and malformed checksums are rejected before
changing the current sound. Routing, held notes, wheel position and scan phase
are excluded. Native Sound/project persistence and parameter locks remain
outside the custom preset format.

The factory package exceeds the old DTII staging allocation. Runtime staging is
now device-specific, with a 262,144-byte maximum in the shared SDK contract and
the selected device's smaller limit enforced by packing and runtime loading.
Use matching new firmware and DKM builds; do not load this package into the old
installed firmware. Generated constants and platform allocation sizes must agree.
