# 54. Module cookbook: what each reference module taught

One entry per module: what it does, what it costs, the traps found while building it, the patterns worth reusing. Every
module PR adds or updates its entry. The agent skill (`.agents/skills/digikit-module/`) links here; facts that every module
needs move into the skill's references. Marks as in docs/FINDINGS.md.

The reference set (Em, 2026-10-21): pluck (machine, physical model), a modal resonator (machine, resonator bank), the
frequency shifter (effect, after the run-time FX adapter of P3d-1).

## digikit/pluck (machine, Karplus-Strong string; both devices)

- **What:** a noise burst excites a delay line of one period; the loop filters it (one-zero damping, a first-order all-pass
  for the fractional period); a comb at the pick position shapes the burst. Parameters DECAY, PICK, BRIGHT, COLOR (the 4
  words the DSP receives). Source: `modules/machines/pluck/src/dsp/pluck.s`, one file for both devices.
- **Cost [D]:** in the engine, one ringing voice adds about 900 instructions per block in the first 0.3 s and 561 on
  average over 2 s; 16 voices about 14,400 (2.5 to 3.1 % of a block) (finding 06, "Modules"). On the rig a steady block is
  under 1,900 instructions with the adapter and guard (`tests/patchkit/test_pluck.py`); the adapter and guard are about 700
  of that. Declared budget: `max_cycles_block` 2200, `max_cycles_note_on` 9000.
- **Memory [D]:** 256 KiB of delay lines (16 voices x 4096 words): half of the Digitakt II run-time DSP area (512 KiB) and
  most of the Digitone II one (320 KiB) (finding 32).
  Size per-voice state for the lowest musical note, not for the arithmetic limit: pluck's 4096-word lines are 258 KiB; 2048 words would still reach the lowest note, about 23 Hz (finding 57: the area is whole 64-byte granules and the loader refuses a module that does not fit with `E_DSP_NOSPACE`).
- **Traps found [D]:**
  - An LFO on TUNE moved the period past what the delay line serves; the all-pass went unstable and Inf/NaN reached the
    send FX of every track. Fix: clamp the pitch, the period (2 .. 4090) and the all-pass coefficient (+-0.9); the
    runtime guard now zeroes a non-finite or too-loud block and disables a machine after 8 faults in a second
    (finding 51).
  - A store of a same-DAG register through an index register ran in the emulator and halted the DSP on the device (rung C,
    finding 49 section 10.7). The build now reports these stores.
  - Knob slot 3 of a Digitakt II SAMPLE clone is the sample word: a parameter there is refused (finding 02, P3c-4).
  - The Digitakt II gives an added machine one SRC page only (finding 50).
- **Device [D]:** played on a Digitakt II 1.17 at rung C4 (finding 47), before the SDK v1 changes. Re-tested by Em on
  2026-10-21 with image rt021 (runtime 0.2.1) and `mise run dk:run -- digikit/pluck --port Digitakt`: MOD_LOAD 1, MOD_DSP 0,
  plays, guard 0 faults, DSP 42-46 %, type 16 (the old PLUCK-D sticky entry holds 18).
- **LFO on TUNE, device result [D]:** at large depth (worst with the random LFO) the sound crackles and is almost silent
  at the extremes; no guard fault. This is the design, not a fault: the period N jumps once per block (no ramp inside the
  block); when the pitch drops, the longer line holds samples that were never excited; when it rises, the shorter loop
  decays fast. A machine that takes pitch modulation must ramp its pitch-dependent state inside the block and keep its
  whole state excited. Fix planned as pluck v2 (fractional delay read ramped over the block, whole line excited at
  note-on, optional TUNE modulation range).
- **Patterns:** `references/dsp-recipes.md` quotes them (parameter word to float, the block loop, noise, damping, all-pass,
  delay line with a mask, pick comb, silence detection to `DK_DONE`).

## core/fx and test/fx-gain (effects adapter and its fixture; both devices)

- **What:** the FX contract (`sdk/dk_fx.h`) is run by `core/fx`, which hooks the first instruction of a post-master function on both devices and
  walks a chain of up to 4 effects. `test/fx-gain` is the smallest effect (0.5 gain). Details and evidence: finding 55.
- **Cost [D]:** an empty chain is 16 instructions per block on the rig (+18 busy instructions in the smoke cell); a chain whose rows are all off 174; one
  effect steady 732 (the 0.5 test effect itself about 210; the adapter's copy, output check and bookkeeping are about 520); a fade block 1065.
- **Traps found [D]:**
  - An entry hook has no stock frame yet: save every register in a static area, as `dsp-voice-dn2.s` does; the DT2 stock function saves its own
    I2, I3 and I5 only, the DN2 one reads R4, R8, R12 and M3 as arguments and the caller needs R14 and R15 back.
  - The context registers (M5-M7, M13-M15, L0-L5, MODE1) belong to the DSP context: save and pin them for the chain, restore before the stock code.
  - `.PKBSS` memory is not loaded; the adapter zeroes an effect's state when it switches on, the rig poisons it to prove that.
  - A master hook at the DAC converter (H0, master-gain / master-drive) is after the USB pack: the USB audio does not carry it (finding 55).
  - Patching a function bars the emulator's AOT regions of the blocks that hold a changed instruction (finding 55, route A; before 2026-10-24 the whole hashed code range): the adapter costs x1.01 on the DN2 at
    `FUN_1c244d` and x1.03 on the DT2 at `FUN_1c80f2`. A hook in a long block or in a function that runs every block still costs the regions that contain it.
- **Patterns:** `references/contract-fx.md`; the rig (`tests/support/fx_rig.py`) and the effects for tests (`tests/support/fx_effects.s`) are templates for
  an effect's unit test.

## digikit/freqshift (effect, single-sideband frequency shifter; Digitakt II and Digitone II, run time)

- **What:** every frequency of the master moves by the same number of Hz (not a pitch shift): a Hilbert pair of allpass chains makes two copies 90 degrees apart, a sine and a cosine of the
  shift frequency modulate them and the sum keeps one sideband. One knob SHIFT (-64 .. +63, bipolar, 0 in the middle), MIX from the framework (default 127). The effect starts as a **send** effect (`route = "send"`, `routes = ["send", "master"]`, finding 65): a send has no dry path, so MIX is the return level and 0 would add nothing; as a master insert MIX 127 means fully shifted (SHIFT 0 passes the sound through the allpass pair, magnitude flat) and MIX is one value for both routes. Before step 5 of the FX routing work the default was 0 on the master.
  Source `modules/fx/freqshift/src/dsp/freqshift.s`; the float32 model that defines the arithmetic operation for operation is `tools/patchkit/freqshift_ref.py`; the effect id is `fshift` (the effect ID of saved kits hashes it with the module id: never rename either).
- **SHIFT mapping [D]:** the knob's float `v` becomes `f = sign(v) 0.63 (2^(|v| / 5.5) - 1)` Hz, computed once per block in the DSP (a degree-4 polynomial for `2^x - 1` with no constant term, so `v = 0` is exactly 0 Hz,
  and `SCALB`): symmetric, monotonic, 0.085 Hz at 1, 0.41 at 4, 1.1 at 8, 4.1 at 16, 12.3 at 24, 34.9 at 32, 96.8 at 40, 266 at 48, 731 at 56, 1,767 at 63, 2,005 at 64 (`freqshift_ref table` prints more). The bipolar knob with `min = -64`, `max = 63` makes the float equal the displayed value
  (the runtime sends `min + span * raw / 0x7f00`, and a display step is 256 raw units), so the table is in displayed units. One step is a slow sweep near 0 and about 13 % of the shift (a whole tone, roughly) near the top.
- **Hilbert pair [D]:** two chains of four first-order allpass sections in z^-2 (the sections of even and odd samples are independent: a polyphase pair, so a section costs 4 operations per sample), one chain delayed by a sample.
  Without that sample the two chains are the two halves of a half-band filter (in phase up to fs/4, opposite above), not a Hilbert pair; with it the phase difference is +90 degrees over the whole band. The coefficients of the published design (Niemitalo,
  as sections `(a^2 - z^-2) / (1 - a^2 z^-2)` and the chain of 0.69 .. delayed) reach 44.2 dB image rejection from 30 Hz to 18 kHz; the repo has its own search (`freqshift_ref design`: Levenberg-Marquardt with Lawson weights from random starts, then Nelder-Mead on the largest phase error) for that band:
  worst phase error 0.55 degrees, image 46.4 dB (the routine measures 46 to 48 dB at 1 kHz to 15 kHz, 70 dB at 260 Hz; below 30 Hz it falls to about 6 dB at 5 Hz). Image rejection of a pair with phase error e is `20 log10 (2 / e)`; the coefficients as first remembered, without the delay, were a half-band pair (the wanted sideband and the image swap at 12 kHz), and as plain z^-1 sections they gave 0 to 30 dB: check the pair on the transfer functions (`freqshift_ref rejection`) before writing assembly.
- **Oscillator [D]:** a 32-bit integer phase accumulator (a turn is 2^32; 1 Hz is 89,478.485 units): it has no rounding and no drift whatever the run length (the phase after N blocks is `528 d + 32 (N - 1) inc` in closed form, and the test compares the DSP's word with it
  after 90,000 blocks). The increment ramps in a straight line over the 32 samples from the last block's (`d = (new - old) >> 5`), the phase is continuous, so a turn of the knob never clicks. sin and cos come from one polynomial: fold the phase to +-a quarter turn with integer ops
  (`R1 = R0 + R0; R1 = R1 XOR R0; IF LT R0 = HALF - R0;`), convert to a float in [-1, 1] and evaluate a degree-7 odd polynomial (error 1.2e-6, spurs at -118 dB); cos is the sine at phase + a quarter turn. The adapter clears ALUSAT, so the integer adds wrap.
- **Cost [D]:** 4,638 instructions per block with core/fx (about 520 of those), so about 4,100 for the effect: chains P 1,200 (18 per sample), chains Q with the mix 1,780 (27 per sample), oscillator 1,050 (32 per sample), the mapping and the pointer set-up about 100; `max_cycles_block` is 4,200. A fade block (the first after switching on) costs 570 more in the adapter. State 664 bytes
  (the 32 section states, two delay buffers, the 64 oscillator values of a block, the phase and the increment). The transposed section `t = c x; y = t + s; u = c y; s' = u - x` needs no register moves: two registers alternate between input and output through the four sections, and with the 8 states and 4 coefficients a chain
  fits the 16 data registers. No multifunction instructions are used yet (the loops would shrink by a quarter).
- **Model match [D]:** the routine's output equals the float32 model to the last bit in every test (rig: 8 SHIFT values and a moving shift, `tests/patchkit/test_freqshift.py`). The first block after switching on is crossfaded by the adapter: compare `rig.scratch()` (the effect's own block), not the master.
- **Traps found [D]:**
  - A module with only a `[[fx]]` record has no state symbol (the runtime reserves it); the FX rig and the conformance suite now reserve a poisoned block for a row with `state=""`, and `pk_conform.fx_spec` reads the `[[fx]]` record (knob ranges give the floats of the parameter words), so a run-time effect is judged by conformance too.
  - The bipolar display shows the signed value under the knob and in the title (`Freq Shift=-42`); the firmware font draws a capital Q like an O in the page title.
  - `ASHIFT` by an immediate is refused by the build (selas-pitfalls): `R1 = -5; R10 = ASHIFT R0 BY R1;`.
- **Tests:** `tests/patchkit/test_freqshift_ref.py` (mapping, Hilbert pair, oscillator, tones on the model), `tests/patchkit/test_freqshift.py` (the routine on the rig: model match, tones at +100, -100 and +2,000 Hz with the image 40 dB down, flat at SHIFT 0, MIX 0 dry bit for bit, level bound, cost, a long run
  under PyPy; a run of a minute is `slow`), conformance (`mise run module:check digikit/freqshift`), the emulator scenarios `fx-freqshift-dt2` and `fx-freqshift-dn2` (page, knob, PCM spectra, Save Kit and Load Kit on the master route; on the Digitone II the send default falls back to the master (no send cells yet), with the same figures: +40 gives +96.79 Hz, -42 gives -124.72 Hz, the image 70.1 dB down, MIX 0 the dry PCM bit for bit; the Digitakt II's scenario also proves the send route, finding 66). A listening demo: `tests/support/freqshift_demo.py`.

## michael/short-loop (effect, short stereo capture; Digitakt II 1.17)

- **What:** an experimental master insert captures 12,000 stereo frames once, then loops them while crossfading with the live input. REC triggers capture, START rotates the playback origin at the next loop boundary, and FADE selects live or frozen audio. Source: `modules/fx/short-loop/src/dsp/short_loop.s`; usage and limits: `modules/fx/short-loop/README.md`.
- **Memory [D]:** 96,064 bytes of descriptor-owned state: 16 metadata words and two 12,000-word float buffers. At 48 kHz this is 250 ms, independent of tempo. Capture copies the input before blending; a frozen buffer cannot be overwritten until the effect is reset.
- **Traps found [D]:** the FX rig's fixed 4 KiB auto-state reserve was too small for this descriptor. `tests/support/fx_rig.py` now sizes each automatic state allocation from its descriptor and includes the row layout in its build cache key; `tests/patchkit/test_fx_rig_allocation.py` covers isolation and bounds. Rotating START also moves the physical capture seam inside the phrase: the envelope must cover both that seam and the phrase boundary. A 16-frame edge fade preserves the exact loop period but introduces an amplitude notch.
- **Tests:** `tests/patchkit/test_short_loop.py` executes the assembled routine behind the FX adapter against `tools/patchkit/short_loop_ref.py`: full capture, stereo isolation, source changes, start latching, both seams, gain ramps, state bounds, context preservation and initialization cost. The standard FX conformance suite applies too.
- **Rig evidence [D]:** all 20 short-loop tests pass, including bit-for-bit output and metadata comparisons with the float32 model. Standard FX conformance completes 24 cases and 3,816 blocks with no reported failures. This is assembled-code simulation, not a firmware or hardware playback result.
- **Firmware kit-switch proof [D]:** `tools/patchkit/pk_short_loop_proof.py` drove real encoder and pattern-button events in OS 1.17 with transport stopped and `SHARC_FAST_AUTO=256,64`. All 35 behavioral checks and seven checkpoint observations pass in `out/runs/short-loop-firmware/report.rechecked.json`. Three kit switches preserved both frozen-buffer hashes, the effect instance and exact cursor advancement from audio-block counts. START raw 8,448 selected frame 3,117. The unprepared A02 kit reset FADE and START; prepared kits recalled the matching controls. Four complete 500 ms PCM captures showed audible source and destination loops, with exact zero output for the silent destination's live mix and after fading back to it. This is full firmware emulator evidence; running-sequencer transitions and hardware remain untested.
- **Idle verifier correction [C]:** the original run failed only because its checkpoint predicate excluded `idle_end`. Independent decoding of the DT2 1.17 image identifies `0xb863df` as the idle loop's unconditional jump back to `0xb863cf`; it is a valid idle checkpoint. The verifier now includes that instruction, matching the SHARC engine's idle-skip guard. Saved-trace revalidation rechecked continuity, PCM and all recorded assertions without another emulator run; the original failed reports remain unchanged. Profile comments and the peer's busy predicate still describe a half-open range, so this correction is specific to the verified DT2 endpoint.
- **Storage initialization limit [D]:** the generic effect-plus-adapter budget is 31,832 instructions (`tools/patchkit/pk_conform.py`, `fx_budget()` plus `FX_ADAPTER_MAX`). `tests/patchkit/test_short_loop_storage_budget.py` executes the same temporary SHARC passthrough effect with 96,064 bytes (250 ms equivalent storage) and 192,064 bytes (500 ms). Activation costs are respectively 25,114 and 49,114 instructions; both subsequent blocks cost 691. Both allocations return, preserve context and adjacent guards, and clear every initially poisoned state word. The extra 24,000 clearing stores account for the entire difference. `modules/core/fx/src/dsp/fx.s` (`_fx_zero`) clears all descriptor state synchronously on activation and faults. This proves an initialization cost above the current conformance budget, not a functioning 500 ms loop or a measured hardware deadline miss.
- **Longer-loop capacity [D]:** `devices/digitakt-ii.toml` fixes the shared run-time DSP region at 524,288 bytes. Code, data and descriptor state share this allocation (`modules/core/runtime/src/rs/src/dsp.rs`, `extent` and `alloc_range`). Float32 stereo at 48 kHz needs 384,000 bytes per second: 2 seconds need 768,000 bytes and 8 seconds need 3,072,000 bytes, before metadata or code. These are respectively one and four bars of 4/4 at 120 BPM; neither fits this region even alone.
- **Storage follow-up [C]:** a changed FX ABI is unnecessary for the single-instance experiment. `michael/long-loop` moves audio into module-owned BSS and retains only 64 bytes of descriptor state. `michael/bar-loop` imports an explicit external reservation from `michael/loop-storage`; see the entries below. The general `Api.alloc` still uses the ColdFire module arena, not DSP sample memory. Full sample-loading lifecycle and hardware access cost remain open.
- **Open [O]:** running-sequencer transitions, transient-free kit-control delivery, hardware playback and heavy-load behavior remain unverified. The buffer is module state, but REC, START, FADE and framework MIX are kit-local; prepared destination kits retained the loop settings in the stopped-transport proof. There is no beat alignment, tempo following, recapture control, longer loop allocation or power-cycle persistence in this proof.

## michael/long-loop (effect, one-second storage proof; Digitakt II 1.17)

- **What [D]:** the existing REC/START/FADE algorithm with 48,000 stereo frames, 384,000 bytes of relocated module BSS and 64 bytes of descriptor metadata. Only metadata is synchronously cleared. A complete replacement capture gates every audio read, including after reactivation and an actual FX output-guard fault. This is an intentional single-row exception to the FX guidance against extra mutable statics, not a general shared-buffer API. Usage: `modules/fx/long-loop/README.md`.
- **Bounds and reset [D]:** all nine tests in `tests/patchkit/test_long_loop.py` pass. They execute assembled code behind `core/fx`, compare complete capture and playback with the float32 model, preserve adjacent guards and hostile context, and demonstrate that old or poisoned audio remains unreadable after reset. Activation stays below 2,000 instructions in the tested calls; the generic adapter-plus-effect ceiling is 31,832. This is an instruction-count bound in the rig, not hardware timing.
- **Conformance [D]:** 24 standard cases and 3,816 blocks pass with no failures. The rig no longer reserves 4 KiB for absent rows; a present row with named state retains its prior fallback. The packed module is 1,652 bytes because BSS is reserved rather than transferred. Audio plus code still counts against the shared 512 KiB runtime DSP area.

## michael/loop-storage and michael/bar-loop (external reservation and eight-second effect; Digitakt II 1.17)

- **What [D]:** a patch-time provider reduces the stock sample allocator from 400 MiB to 392 MiB and publishes one 8 MiB DSP reservation. The effect records 384,000 float32 stereo frames (3,072,000 bytes), eight seconds or four bars of 4/4 at 120 BPM. Duration remains fixed in seconds. The shared module area holds code and 64 metadata bytes; activation additionally initializes eight canary words, never the audio. Usage and controls: `modules/fx/bar-loop/README.md`; patch details: `modules/tools/loop-storage/README.md`.
- **Reservation coordinates [V]:** the six hash-anchored ColdFire operand patches bound normal allocation at offset `0x18800400`. An independent agent checked the pinned MAIN bytes and instruction roles, the sender's subtraction at `0x40153a1e` and shift at `0x40153a2e`, and the DSP copier's shift at `0x1c404e` and base addition at `0x1c4053`. The external DSP interval is `0x9ca2b9c8..0x9d22b9c8`, ending exactly at the original preview region. The two preview destination operands, unrelated matching table literal, and DSP preview-capable page bound `0x19200` remain unchanged. Adding the ColdFire bias again would overlap 1,024 preview bytes. This verifies coordinates and patch scope, not every possible writer.
- **Allocator execution [D]:** `tools/patchkit/pk_loop_storage_proof.py` passes a paired stock/patched execution of the actual ColdFire helpers against identical synthetic allocation records. Capacity/free getters, exact new capacity, the next 8 KiB allocation quantum, the old capacity, nonempty tail and gap cases are checked. An audit requires MAIN to differ only at the six reviewed operands. Evidence: `out/runs/long-loop/allocator/report.json`. This does not load hundreds of MiB of samples or establish every firmware writer.
- **Import and guards [D]:** the DT2 DSP import table optionally exposes `_loop_buffer_info`; the effect requires it. The record carries magic, version, byte base and capacity. The consumer validates alignment and subtraction-based external bounds before every audio access. A 32-byte canary immediately after audio is initialized with eight `0x5a17b00f` words and checked on subsequent calls. Corruption faults through the real adapter and invalidates capture. One provider serves one consumer; duplicate module IDs are already refused, but this is not a general multi-consumer allocator.
- **Missing-provider boot [D]:** a separate actual-firmware boot without the reservation passes ten checks: sine loads, bar-loop returns `E_DSP_IMPORT (-32)`, safe mode remains off, the UI is reached, and no bar-loop module, DSP allocation or FX row remains. The optional export is observed as zero. Evidence: `out/runs/bar-loop-missing-provider/report.json`.
- **Import trap [D]:** the first positive boot also returned `E_DSP_IMPORT`: an optional alias from `_dd_loop_buffer_info` to the provider's global name resolved to zero. `packages/patchkit/src/apply.rs` resolves manifest aliases through primitive symbols and anchors, but not renamed object globals. Referencing `_loop_buffer_info` directly fixes the binding without changing the linker. The generated firmware table now matches the provider symbol; manifest and built-object regressions cover it. The original failed run is retained under its unique report name.
- **DSP tests [D]:** all 35 cases in `tests/patchkit/test_bar_loop.py` pass, including complete eight-second stereo capture, exact model comparisons, START, stale-audio invalidation, read/write bounds, malformed descriptors and canary faults. Standard FX conformance passes 24 cases and 3,816 blocks. Its explicit provider fixture permits only audio plus canary writes and keeps the provider record read-only; unknown imports still fail. That fixture supplies test memory and makes no firmware-ownership claim.
- **Eight-second firmware proof [D]:** the corrected image passes all 45 checks in `out/runs/bar-loop-firmware/report.json`, in one actual OS 1.17 emulator boot with transport stopped and `SHARC_FAST_AUTO=256,64`. It captures exactly 384,000 frames per channel into the reservation; every recorded second contains finite audible input. Three real PTN/TRIG kit changes preserve both buffer hashes, the canary and exact cursor advancement. START raw 7,680 selects frame 90,708 and prepared kits recall it with FADE/MIX. All seven checkpoints are independently matched to idle DSP observations. Four 8.05-second PCM recordings each contain 386,400 stereo frames; analysis uses one complete 384,000-frame loop. Source/destination-loop RMS is respectively 0.0286122260/0.0286120994, while the destination live and faded-live windows are exactly zero. The complete-file module SHA-256 is `b50ff219fbdd0cd4cabd5d4c3f63083f4e45e34de8f8583cba1837b3171f05d7`. This is accelerated firmware evidence, not interpreter parity, running-sequencer or hardware validation.
- **Validation boundary [D]:** the required `verify:pre` ran its 26 selected Python files. Its custom-author routing and legacy 4 KiB poison assumptions were corrected, with 15 routing checks and two frequency-shifter boundary checks passing on rerun. The complete pre-check remains failing: this workspace lacks the pinned ColdFire Rust compiler, C compiler frontend and Cargo Nextest; WSL Git path handling also fails the global path scan. Changed-file path checking passes under Windows. Rebuild checks on unchanged modules also differ: an in-memory audit confirms identical payloads for dynfx, gain fixtures, dyndsp, pluck and sine, but different symbols/relocations for dynreg (and DN2 section bytes). Those original objects were preserved. Evidence is under `out/runs/long-loop/`, including `verify-pre.log` and `object-provenance.json`; this is not a clean merge-gate or hardware result.
- **Open [O]:** full sample loading, deletion, compaction, project reload, sampling/recording, preview interaction and restart tests with canaries; real hardware timing and heavy load; running-sequencer transitions, beat quantization, tempo-dependent duration and global controls. The reservation has space for about 21.8 seconds of float32 stereo, but the implemented effect uses eight seconds. Kit-local REC/START/FADE/MIX and one capture per activation remain the earlier proof's constraints.

## michael/pattern-position (sequencer observation provider; Digitakt II 1.17)

- **What [D]:** a patch-time bridge snapshots native master step, substep, effective wrap length, start/resume generation and transport, then publishes them in an 80-byte DSP record before stock command dispatch. It uses 16 words of the existing audio-frame tail and leaves 155 code-link payload words. Consumers require `_pattern_position_info`; missing providers fail import. See `modules/tools/pattern-position/README.md` and [finding 68](68-pattern-position.md).
- **Trap [V]:** the scheduled next-step counter and pattern pointer can lead the reported current position. Distinct fields and snapshot/transmit timestamps preserve that distinction; they must not be silently relabeled as audible position.
- **Open [O]:** this is the prerequisite for selected-step loop capture. The eight-second effect's REC/START/FADE behavior is unchanged; timing alignment and clock/transition cases need their own evidence before a step control is connected.

## digikit/remote (a service module: SysEx commands of its own; both devices)

- **What:** a run-time module that registers commands with `Api.register_cmds` (api 1.2) and calls the runtime's imports `input_key` / `input_turn` (core/input). One C file, `modules/tools/remote/src/c/remote.c`; the packed `.dkm` is identical for both devices (1032 bytes; 2088 bytes **[C]** since its settings menu, phase 4 of docs/plans/sdk-api.md).
- **Shape:** `dkm_init(api)` registers one range per `register_cmds` call; a handler is `int h(cmd, seq, body, len, out)` and returns the reply length or a negative status; it runs in the MIDI task, so it is short and never waits.
  Use a range that `sdk/sdk.toml` `[protocol.ranges]` reserves; a new service adds its range there first (`mise run gen:modules`).
- **Guard [C]:** the REMOTE switch and the `[protocol] guarded` ranges are gone (phase 4 of docs/plans/sdk-api.md): a service module is on when its check mark in DIGIKIT > MODULES is set. A module that needs settings exports `dkm_menu` (`DK_MENU` of `<dk/ui.h>`).
- **Traps [D]:** a request number is 6 bits (bit 6 marks a reply), so a range cannot start at 0x40; an import that the image does not have (core/input missing) fails the load with `E_IMPORT`;
  the firmware clamps a flushed turn to 30 detents, so the module keeps a pending estimate and returns the delta it took.
- **Test:** scenario `remote-control` (live, both devices), fixtures `test/svc-echo` and `test/input-probe` are smaller templates.
